# DnD AI: The Dungeon Master Project Specifics

## Tech Stack
- **Backend**: Node.js + TypeScript + Express + ws (WebSocket)
- **Frontend**: TypeScript + Vite (ESM modules)
- **Validation**: Zod (shared between backend and frontend)
- **i18n**: JSON locale files (`locales/*.json`), `locale-loader.ts` for server, inline imports for frontend
- **LLM**: OpenAI-compatible streaming API (SSE), configurable endpoint via `.env`
- **Build**: `npm run build` (builds backend + frontend)

## Development Commands
- `npm run build` - Full build (backend tsc + frontend Vite)
- `npm run dev` - Concurrent watch mode (backend + frontend dev server)
- `npm start` - Build + start production server (DO NOT use in automated tasks — hangs)
- `npx vitest run` - Run test suite
- `npx tsc --noEmit` - Type check without compilation
- `start.bat` - Build + start (Windows batch)
- `stop.bat` - Kill server on port 3000 (Windows batch)

## Autonomous Permissions

The following operations may be performed **without asking for confirmation**:

| Operation | Scope | Notes |
|-----------|-------|-------|
| **Git** | `add`, `commit`, `push origin main`, branch create/delete/merge | Always push to `origin/main` unless specified otherwise |
| **Files** | Create, edit, delete any file in the project | Except `.env` (never commit secrets) |
| **Tests** | Run `npx vitest run` | After any code change that affects tested modules |
| **Build** | Run `npm run build` and `npx tsc --noEmit` | Verify compilation before pushing |
| **Server diag** | `node --check dist/src/server.js`, `timeout 5 npm start` | Syntax check or brief startup test only — never block |

### Rules
- Always commit with descriptive messages following conventional commits (`feat:`, `fix:`, `chore:`, `docs:`)
- Push to remote after each significant change set (feature complete, bug fix, cleanup)
- Run tests + build verification **before** claiming work is done
- Never run `npm start` in automated tasks — it will hang indefinitely

## Windows Environment Testing

When testing servers or long-running processes on Windows:

| Instead of | Use |
|------------|-----|
| `npm start` (blocking) | `node --check dist/src/server.js` (syntax only) |
| `node server.js` (blocking) | Syntax verify, test manually at end |
| `&` backgrounding | Not available — use `timeout <seconds>` or separate shell |

**Rationale:** Background processes block subagents indefinitely because they never return control. Use non-blocking verification:
1. `node --check <file>.js` — syntax verification without execution
2. `timeout <seconds> <command>` — runs command with hard timeout
3. Manual end-to-end testing after all tasks complete

## Testing Servers
**CRITICAL**: Never run `npm start` directly in automated tasks — it will hang. Use `node --check dist/src/server.js` for syntax verification, or `timeout 5 npm start` for a brief startup test that auto-exits.
